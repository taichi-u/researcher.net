# researcher.net デザイン調査と実装方針

調査日: 2026-10-23。以下は公式サイトの実画面・一次資料に基づく観察と、このプロジェクト向けの設計判断を区別してまとめたもの。

## 参照した実例

- **[Connected Papers](https://www.connectedpapers.com/)** — 公開サンプル「Science mapping software tools」をブラウザで確認。左の文献索引、中央のグラフ、右の選択内容という三領域が、全体像と根拠を往復する用途に合う。細い区切り線、常設検索、選択ノードの輪郭強調を参考にする。元サービスの線は類似性を表すため、本サイトの共著線とは意味が異なる。[説明](https://www.connectedpapers.com/about)
- **[Litmaps](https://docs.litmaps.com/en/articles/9057179-create-a-litmap)** — 起点を検索して関連研究へ広げる公式の操作説明を確認。研究者検索→近傍→論文の導線に応用する。ランディングページより探索画面を優先する。
- **[Open Knowledge Maps](https://openknowledgemaps.org/faq)** — 配置の意味と限界を明示する点が有用。本サイトにも「配置は共著ネットワークの見やすさのため。地理的位置や研究者の価値を表さない」と短く記す。
- **[Observable Plot の資料ページ](https://observablehq.github.io/plot/getting-started)** — ブラウザで確認。見出し、細い罫線、余白、索引で長い技術情報を整理する方法を、詳細パネルの論文・所属・出典に応用する。広告用トップページの外観は採用しない。
- **[IBM Design Language: Data visualization](https://www.ibm.com/design/language/data-visualization/design/basics/)** — 色・形・線幅には意味を与え、全体像→絞り込み→必要な詳細という操作順序にする指針を採用する。画面を装飾するための色は増やさない。

ロゴ、独自のイラスト、コピー、画面そのものは複製せず、情報の構造と操作の原則を取り入れる。

## 「AIっぽさ」への対応

[NN/g のAIプロトタイピング評価](https://www.nngroup.com/articles/ai-prototyping/)では、具体的な文脈・視覚仕様がないと汎用的な外観へ寄りやすく、詳細指定後も情報の優先順位、コントラスト、余白に問題が残った。「AIっぽくない」は客観的な単一スタイルではない。本サイトでは、研究者・論文・出典が最初から見える**研究アトラス**という用途に仕様を固定する。

巨大な宣伝見出し、グラデーション背景、光るノード、意味のない宇宙装飾、すべてを同じカードに収める構造は使わない。書誌情報の読みやすさ、安定した地図、短い操作文、実際の収録範囲によって個性をつくる。色とフォントだけ変えて完成扱いにせず、実データの長い氏名・所属・論文名で画面を確認する。

## 配色と書体

背景 `#F7F6F0`、面 `#FCFBF7`、本文 `#232B2B`、補足 `#5D6562`、区切り `#D8D9D0`、操作 `#275D50`。低彩度の紙面と濃い文字を基本に、色をデータへ集中させる。通常面に影は付けない。

| テーマ | ノード色 |
|---|---|
| 惑星間・スイングバイ | `#466B91` |
| 低推力・ソーラーセイル | `#9F683B` |
| 多体系・月近傍 | `#756A9C` |
| 小天体近傍 | `#5A7D68` |
| ランデブー・編隊 | `#4B8790` |
| 数値最適化・最適制御 | `#B26150` |
| ロバスト・確率的設計 | `#948237` |
| 機械学習・自律設計 | `#9C6C88` |

これは本サイト向けに選んだ配色であり、特定機関の公式パレットの転載ではない。背景に対する通常色の計算上のコントラストは、本文13.36:1、補足5.54:1、テーマ色3.52〜5.14:1。テーマ色を小さい本文には使わない。これだけで色覚特性への対応や画面全体の適合を保証するものではない。テーマ名と絞り込み、文字による詳細を常に併用する。[W3C: 色の使用](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)

- UI: `system-ui, -apple-system, BlinkMacSystemFont, "Hiragino Kaku Gothic ProN", "Yu Gothic", Meiryo, sans-serif`。日本語をOS標準書体で表示し、外部フォント通信と大きな日本語フォントの初期転送を避ける。
- ロゴ文字だけ: `Georgia, "Times New Roman", serif`、26px。英字の研究誌らしいアクセントとして限定使用する。OS書体をCSSで指定し、フォントファイルは再配布しない。
- 本文14px/行高1.65、人物名25px/1.25、領域見出し16px、詳細本文12px、補足10〜12px。本文は400、見出しは600。年・件数は `font-variant-numeric: tabular-nums`。日本語に大きな字間や全面大文字の欧文装飾を混在させない。
- 将来、端末間で字形を統一する必要が出た場合は、[Noto Sans JP（OFL）](https://github.com/google/fonts/blob/main/ofl/notosansjp/METADATA.pb)をライセンス同梱でセルフホストする。初版はシステム書体を採用する。

## 画面と図形

デスクトップは64pxヘッダー、左268pxの検索・絞り込み・索引、中央可変幅の地図、選択時に右350pxの詳細。横方向の区切りは1px、基本間隔は8/16/24px、操作部品の角丸は3px。地図を最も大きく取り、件数は簡潔な書誌情報として扱う。詳細はカードの連続ではなく、罫線で区切った読み物とする。

研究者は円、研究室は四角、研究課題は菱形。共著は実線、指導は矢印、研究室・課題への参加は破線。線幅は共著件数を示す。人物の点は固定サイズとし、選択中のみ輪郭を強める。大きさを評価順位と見せない。主テーマで色を決め、詳細には複数テーマを文字で列挙する。選択は濃い外周リング、近傍線と名前の強調で示す。

初期画面の名前は起点研究者の姓に絞り、拡大・hover・選択時に詳細な名前を出す。再フィルター時に座標を動かさず、非対象を除いて空間の記憶を保つ。線のテーマ名は選択時に表示し、全線へ常時ラベルを付けない。

## 操作と確認項目

検索欄、切替、ズーム、全体へ戻るに明示的ラベルを付ける。キーボードでは検索結果一覧から人物へ到達できる。フォーカス輪郭は2px、通常の操作ターゲットは44pxを目標とする。これはWCAG AAの24px最低値より余裕を持たせた設計判断。[W3C: ターゲットサイズ](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

hover情報はEscで閉じられ、ポインターを説明へ移しても消えないようにする。同じ情報はクリック後の詳細でも読める。[W3C: hover/focus](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html)

900px未満ではフィルターを開閉式、詳細を閉じるボタン付き下部パネルへ変更。地図のズーム・リセットはパネルに隠さない。検索と一覧を代替の探索経路にする。狭い画面で三列を縮小しない。

確認項目: 400人の密度、長い氏名、テーマ未収録、ゼロ件、絞り込み後の選択解除、画面拡大、狭幅、キーボード操作、フォーカス復帰。実施結果と未検証範囲は `../qa/browser-verification.md` に記録する。動きは必要な表示変化に限定し、`prefers-reduced-motion`を尊重する。
