# researcher.net デザイン・操作・描画の調査

調査・更新日: 2026-10-26。対象データは2026-10-23の固定スナップショット。

## 今回の判断

目指すのは、研究者名、共著、論文、出典が読める索引。「AIっぽさ」を特定の色やフォントの性質として断定せず、実画面で気になった均一な太字、説明的な呼びかけ、細かな区切り、常時表示される大量の線を見直した。

ユーザーの指摘を受け、「研究者を探す」は「研究者」へ、検索欄は「氏名・所属・論文名」へ変更。操作を見出しで言い直す表現を減らした。文字組みも、全体を同じゴシック体にする構成から、名前のセリフ体と操作のゴシック体を使い分ける構成へ変更した。

## 参考サイトから抽出した要素

公式ページと公式資料を参照。Are.naはブラウザの実画面でも確認し、ほかはページの構造・公開資料を調査した。外観の観察と、本サイトへの適用判断は同一ではない。

| 参照先 | 調査した点 | 本サイトで試した要素 |
| --- | --- | --- |
| [Are.na](https://www.are.na/) | 白地、短い語彙、余白、内容中心の階層。独自書体も含めた一貫性 | 背景を静かにし、操作の呼びかけを減らす。独自書体・ロゴは取得しない |
| [Library of Congress](https://www.loc.gov/) | 常設の検索と資料への複数の入口 | 最初に検索と索引を置き、人物一覧から根拠まで到達できる構成 |
| [Project Gutenberg](https://www.gutenberg.org/) | 検索・分類・書名が中心の図書館としての構造 | 宣伝文より実際の収録情報を優先。小さな件数や分類を補足として扱う |
| [Nature](https://www.nature.com/) | 見出し、記事名、著者、日付、記事種別の階層 | 人物名を大きく、所属と件数を小さく。名前と補足で書体を分ける案 |
| [DensityDesign Lab](https://densitydesign.org/) | 可視化の研究、活動・出版物を分類して読む構成 | 図と資料の往復を中心にし、不要な装飾を増やさない |
| [Rijksmuseum Collection](https://www.rijksmuseum.nl/en/collection) | 一覧・発見・個別資料への導線 | 概観と選択内容の切り替え。作品画像や美術館固有の表現は流用しない |
| [Connected Papers](https://www.connectedpapers.com/about) | 起点と関連文献をグラフで読む方法 | 一覧・地図・詳細の三領域。元サービスの線は類似性、本サイトは共著という意味の違いを保つ |
| [Open Knowledge Maps FAQ](https://openknowledgemaps.org/faq) | 地図の意味と読み方を説明する方法 | 配置が地理位置や研究者の評価を意味しないことを短く明記 |

これは、複数の参考例の構成原則を実データに置き換えた試作。元サイトをスクリーンショットから複製したものではない。[NN/gの最小限のデザインの解説](https://www.nngroup.com/articles/aesthetic-minimalist-design/)も参照した。見た目の簡素さだけでなく、利用目的に必要な情報を残すことを判断の軸にした。

## 書体と文言

- 人物名とロゴ: **Source Serif 4 Regular**。一覧16px、選択した人物名30px、グラフの起点名は画面上13px。名前を太字にする代わりに書体とサイズで区別する。
- 日本語の領域見出し: OSの明朝体（Hiragino Mincho ProN / Yu Mincho）。実際の字形は端末で異なる。
- 操作、所属、注記: Helvetica Neue / Arial / Hiragino Sans / Yu Gothicなど。通常の文字サイズは11〜14px。数字は桁を揃える。
- グラフはCanvasにも同じ欧文書体を指定する。数字を含む書体名は引用符付きにし、フォント読み込み後に初期化する。
- 「研究者を探す」→「研究者」、「線を整理」→「主要な線」、「系譜を見る」→「研究の系譜」。必要なエラー説明やアクセシビリティラベルは残す。

[AdobeのSource Serif公式リポジトリ](https://github.com/adobe-fonts/source-serif)からRegularのWOFF2（76,260バイト）を取得。ファイルは変更せず、[SIL Open Font License](../web/assets/fonts/SOURCE-SERIF-LICENSE.md)を同梱し、サイト自身から配信する。閲覧時にGoogle Fontsなどへの接続は発生しない。

取得元: `https://raw.githubusercontent.com/adobe-fonts/source-serif/release/WOFF2/TTF/SourceSerif4-Regular.ttf.woff2`。
SHA-256: `6b053e98f0838afe81f3e784727be4583a7c13bb42f198dc5202ecffee0aaee0`。

## 画面の構成

左の索引は304px、詳細は370px。大画面は少し広げ、900px以下では検索を開閉式、詳細を下部パネルにする。初期状態では絞り込みを畳み、人物一覧を広く取る。人物行や詳細の各節には横罫線を重ねず、余白で区切る。大きな領域の境界、詳細のタブ、論文レコードの区切りには細い線を残す。

共著図は固定配置を保ち、フィルター変更で再レイアウトしない。研究者は円、研究室は四角、課題は菱形。指導は矢印、研究室・課題は破線。表示されていない種類の凡例は隠す。ノードを誤って移動しないよう、ドラッグによる座標変更は無効化した。

グラフの点を大きな操作ボタンにすると密集時に重なるため、人物一覧を同じ内容へ到達する代替経路として維持する。[W3Cのターゲットサイズの説明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)でも、密な地図と同等の操作経路について扱っている。実機・スクリーンリーダーを含めた完全な適合判定は未実施。

## 誤クリックの対策

人物選択中は、その人物に接続する線だけを操作対象にする。無関係な線にはCytoscapeの`events: no`を設定し、クリックとhoverを通さない。イベントハンドラー側にも条件を置く。人物名ラベルには`text-events: yes`を指定する。

薄い線をクリックしたときに選択が解除されることも防ぐため、背景クリックでは選択を維持する。解除は「選択解除」か詳細の閉じるボタン。別の人物は引き続き選択できる。関係の一覧からも個々の共著論文へ到達できる。

## 大量の線と遅延読み込み

[Cytoscapeの公式性能ガイド](https://js.cytoscape.org/#performance)は、線の数、ラベル、スタイル更新、描画ピクセル数が負荷に影響することを説明している。[Sigmaの公式資料](https://www.sigmajs.org/reference/settings/)でも、線のイベントと移動中の描画にはコストがある。[Chromeの性能計測手順](https://developer.chrome.com/docs/devtools/performance)を参考にCDPでCPUを4倍に抑えて比較した。

採用した対策:

1. 全体図は各人物の共著件数上位2関係の和集合を表示。関係を持つ人物が図から孤立しないようにし、指導・研究室・課題の線は省略しない。
2. 全体表示に対するズーム比1.8倍で上位4関係、3.2倍で全線を追加する。人物選択時は、その人物の関係を件数によらず追加。「すべての線」と周辺表示でも全関係を利用できる。
3. 件数・検索・論文・根拠の集計には、描画省略前の全データを使う。表示本数を別に明記する。
4. ズームの各フレームで全スタイルを作り直さず、操作終了160ms後に更新する。人物選択などの明示的な移動では、その場で大きさを安定させる。
5. `cy.batch()`で更新をまとめ、線は追加・削除の差分で更新。移動中の線の描画を省略し、高密度画面でもCanvasの比率を最大1.5に抑える。これは表示の精細さとのトレードオフ。
6. 初期JSONには検索と集計に必要な書誌情報だけを含める。著者の掲載時所属、元の名前、ORCID、Crossrefなどの完全な情報は64分割し、「全著者・掲載時の所属」を開いたときに取得する。同じ分割の通信は共有し、失敗後は開き直して再試行できる。

[Web Worker](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers)、描画範囲による間引き、WebGLへの移行も調査した。今回の主な問題は全スタイルの連続更新と線の常時描画だったため、ライブラリの置き換えやWorkerの導入は見送った。将来の増量時は再計測して判断する。
